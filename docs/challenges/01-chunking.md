## 문제 상황
- QnA와 자료 추천은 강의 자료 PDF에서 현재 섹션과 관련된 조각을 찾아 근거로 씁니다. 조각을 어떻게 나누느냐에 따라 찾아오는 내용이 달라집니다.
> 처음에는 PDF 한 쪽을 조각 하나로 썼고(page), 이때 검색 상위 4개 중 섹션과 관련 있는 조각은 75.6%였습니다. 글자 수로 일정하게 자르는 방식(fixed)은 구현이 단순하지만, 조각이 문장 중간에서 시작하거나 끝납니다.

## 해결 방법

### 1. 분할 방식 네 가지를 같은 기준으로 비교합니다.

| 방식 | 자르는 기준 |
| :--- | :--- |
| **page** | 쪽 하나를 조각 하나로 사용 (기존 방식) |
| **fixed** | 문서를 이어 붙인 뒤 글자 수만 보고 자름. 문장·단어 경계를 보지 않음 |
| **recursive** | 문서를 이어 붙인 뒤 토큰 수 기준으로 자르고 이웃 조각과 겹침 (`RecursiveCharacterTextSplitter`) |
| **semantic** | 이웃 문장 묶음의 임베딩 거리가 크게 벌어지는 곳(주제 전환)에서 자름 |

- **같은 질의, 같은 채점** — 네 방식 모두 섹션 확정 요약을 질의로 강의 자료 조각을 검색하고, 상위 4개 조각이 섹션과 관련 있는지를 `gpt-6.1-terra`가 관련/무관으로 판정합니다. 지표는 상위 4개 중 관련 있는 비율(Precision@4)입니다.
- **같은 섹션끼리 짝지어 비교** — 두 방식의 차이는 같은 섹션의 결과끼리 짝지은 부트스트랩 10,000회로 95% 구간을 구합니다(`eval.compare`). 구간이 0을 포함하지 않아야 차이가 있다고 봅니다.

> **평가 데이터는 어떻게 만들었나?** — 생성형 AI로 만든 강의 자료·스크립트를 TTS로 읽고, 그 음성을 실제 서비스의 녹음 경로로 넣어 섹션별 전사와 확정 요약을 수집했습니다. 검색 질의가 실제 서비스에서 만들어지는 요약과 같은 경로로 만들어집니다.

### 2. 문장 사이 의미가 바뀌는 곳에서 자릅니다.

- **semantic 분할** — LangChain `SemanticChunker`와 같은 방식으로 경계를 정하고, 슬라이드용 문장 분리와 크기 보정, 문장 겹침을 더했습니다.
  1. 줄바꿈·글머리표·문장 끝으로 문장을 나눕니다.
  2. 문장마다 앞뒤 1문장을 붙인 묶음을 임베딩합니다.
  3. 이웃 묶음의 코사인 거리가 문서 안 거리 분포의 백분위수 기준을 넘는 곳에서 자릅니다.
  4. 최소 토큰보다 짧은 조각은 이웃과 합치고, 최대 토큰보다 긴 조각은 문장 단위로 다시 나눕니다.
  5. 각 조각 앞에 이전 조각의 마지막 문장을 붙여, 경계 근처의 문장이 양쪽 조각에 모두 담기게 합니다.

### 3. 설정값은 dev 데이터로 정하고, 비교는 test 데이터로 합니다.

| 구분 | 강의 | 용도 |

| **law** | 3강 (인공지능과 법) | 글자 수 분할(fixed)과 비교 |

- **dev 63섹션에서 설정값 선택** — semantic은 백분위수, 문장 겹침, 최대 토큰을 바꿔 가며 측정했고, 가장 높은 D2 설정을 기본값으로 정했습니다.

- **test 133섹션에서 방식 비교** — dev에서 정한 설정 그대로 test 데이터에서 세 방식을 비교했습니다.

### 4. 글자 수 분할과는 조각 길이를 맞추고 자르는 위치만 비교합니다.

- **조각 길이 통제** — 조각이 길면 한 조각에 담기는 내용이 많아져 결과가 달라질 수 있습니다. 그래서 fixed의 글자 수(264자)를 semantic 조각의 평균 글자 수에 맞춰, 자르는 위치만 다르게 했습니다.
- **끊긴 조각 진단** — 시작이나 끝이 문장 중간인 조각을 "끊긴 조각"으로 세었습니다(`eval.diagnose`).

| 실험 | 방식 | 조각 수 | 평균 글자 | 끊긴 조각 | Precision@4 | semantic과의 차이 (95% 구간) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **E21** | **semantic** | 111 | 245 | **0.0%** | **94.3%** | - |
| E20 | fixed | 75 | 246 | 100.0% | 87.4% | +7.0%p [+3.9, +10.1] |
| E23 | recursive | 79 | 238 | 55.7% | 90.0% | +4.4%p [+1.8, +7.0] |
| E22 | page | 32 | 576 | 0.0% | 84.8% | +9.5%p [+5.9, +13.2] |

## 효과

- **기존 방식보다 높은 검색 정확도**
  - test 133섹션에서 Precision@4가 쪽 단위 분할 75.6%에서 semantic 88.5%로 12.9%p 올랐습니다.
  - QnA와 자료 추천이 근거로 쓰는 강의 자료 조각 중 섹션과 관련 있는 비율이 그만큼 높아졌습니다.

- **문장이 끊기지 않는 조각**
  - 조각 길이를 같게 맞춘 조건에서 fixed 조각은 모두 문장 중간에서 끊겼고, semantic 조각은 끊긴 것이 없었습니다.
  - 같은 97섹션에서 semantic은 fixed보다 7.0%p, recursive보다 4.4%p, page보다 9.5%p 높았고, 세 비교 모두 95% 구간이 0을 포함하지 않았습니다.

- **설정 한 줄로 바꿀 수 있는 분할 방식**
  - 네 방식이 같은 인터페이스로 구현되어 있어, `RAG_CHUNK_STRATEGY` 값만 바꾸면 코드 수정 없이 분할 방식을 바꿀 수 있습니다.
  - 분할 세부값(`RAG_CHUNK_*`, `RAG_SEMANTIC_*`)도 환경변수로 조정합니다.

- **다시 돌려볼 수 있는 비교**
  - 측정 조건과 결과가 실험마다 보고서로 남아 있고, 같은 스크립트로 다시 측정할 수 있습니다.
